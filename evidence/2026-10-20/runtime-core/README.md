# Persistent runtime hardening evidence — 20 October 2026

This evidence belongs to the maintainer repository, outside the installable package.

The coordinator now binds role model, cwd, on-request/user approval routing and local sandbox on both start and resume. It refuses unvalidated permission-profile responses. Builder roots must exclude canonical planning state, the active plugin implementation and selected judge configuration; persisted bindings are rechecked before execution. Native approvals cannot widen worker shell/file permissions, including when an operator supplies an otherwise valid capture receipt.

Native connected tools are disabled per invocation, without copying personal configuration or credentials. Effective configuration and the actual MCP inventory are checked; connected apps and native computer/browser access must be disabled/denied. Explicit incompatible computer/browser grants cause failure rather than an isolation claim. The native shell filesystem boundary is still distinct from universal protection against arbitrary external processes, concurrent user Git/Beads edits or all possible future native tools.

Control commands bind exact role, thread and turn. Interrupt acknowledgement does not imply completion; steer uses the native expected-turn precondition; failed/unknown work is never automatically replayed. The watchdog marks missing activity as reconciliation required. Explicit recovery reads the latest native terminal turn. Fresh-session migration requires exact latest terminal evidence, preserves old native history and records schema hashes. Native resume cannot refresh dynamic tool definitions in the current protocol, so missing/changed schema bindings fail closed until explicit migration.

Trusted terminal capture runs in a separate worker with no SQLite or native RPC access. The main event loop remains available to expire/revoke requests, process native completion and handle controls; receipt handling rechecks current scope. Gate acceptance receives exact current task/head/criteria/evidence scope and delegates final verification to the gate service. Unstructured `reply` files cannot manufacture operator provenance. Automated terminal tests elsewhere are synthetic channel tests, not observed human acceptance.

Judge configuration is explicitly selected by the operator's roster `judge_config` absolute path, normalized and pinned in protected coordinator storage. Changed source/config snapshots fail before a provider invocation. There is no provider fallback or human authority inferred from a judge answer. `delivery_judge` is advisory by default; protected evaluation must be requested explicitly and is subject to the provider adapter's calibration policy.

## Independent native Git capability extension

The original native builder lane could edit product files but could not create Git index locks. `native-git-worktree.json` records actual add failure with unchanged HEAD, not a successful delivery implementation. This prompted a supported opt-in role capability, `git_metadata_write: true` (default false).

Writable Git metadata is supported only for independently prepared stores whose common Git directory is inside that builder's own cwd. Stores must have a symbolic local branch, no object alternates, no hardlinked objects or writable metadata files, no shared store across roles and no overlap with planning state or the active package implementation. Independent clones prepared with `git clone --no-hardlinks` are suitable; this runtime never silently clones or rewrites user repositories. Shared linked-worktree writable Git remains unsupported. The role's branch/store directory identities and computed permission paths are pinned; start/resume and controlled operations recheck them. Changed configurations require explicit terminal session migration/repreparation rather than silent rebinding.

The exact allowlist consists of the independent objects directory; the bound branch ref and reflog plus their lock files; `packed-refs.lock` only; and the role's `index`, `COMMIT_EDITMSG`, `HEAD`, `logs/HEAD`, `AUTO_MERGE` and their exact lock files. Neither the whole `.git` directory nor `packed-refs` contents, Git config or hooks are writable. Effective native roots must exactly match this computed list. Normal native sandbox, on-request/user approvals and hooks remain in place; no parent/unsandboxed Git add/commit shortcut is used.

All builders receive checked `TMPDIR=<worktree>/.delivery-evidence/tmp` and `TMPPREFIX=<same>/zsh`, without a global `/tmp` grant. Persistent role instructions also identify the actual package, available skill phases, canonical planning root and peer roles/lanes; those paths convey no additional authority.

- `unit-tests-git-extension.txt`: **35 owned unit/protocol tests passed before the final reserved-profile audit fix**, including independent-store permissions, default capability restrictions, shared worktree/alternates/hardlink denial, immutable branch bindings and package/planning context on native start/resume.
- `native-git-production-v3.json` (repeated after the audit fix in `native-git-production-v4.json`): **actual production Coordinator + real model + default `/usr/bin/git`** creates a synthetic commit in the disposable independent clone. ## Final independent audit regression

An independent source audit found that caller-supplied `_git_profile` could survive raw role validation when `git_metadata_write` was absent/false and influence native roots. `profile-injection-before-fix.txt` reproduces the failing negative test. Raw roster and persisted role specifications now reject the reserved `_git_profile` and `_builder_tmpdir` fields; derived profiles are computed only from validated paths and pinned store state. Native option generation and effective-policy verification independently refuse derived Git roots without explicit true opt-in.

`unit-tests-final.txt` records **36 owned tests passing**, including absent/false opt-in attempts to inject the planning root and read-only reserved-field injection. `native-git-production-v4.json` repeats the current production-path real-model test after this fix: commit and add return zero, commit stderr is empty, heredoc succeeds, both temporary variables stay inside the worktree and all protected write attempts are denied. Its structured acceptance checks all pass. Prior v3 acceptance and the reproduced audit regression remain preserved. Final repository-wide reruns are root's separate evidence category.
