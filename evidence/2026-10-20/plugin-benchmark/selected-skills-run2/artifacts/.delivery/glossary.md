# Glossary — translator handover

> Owner and terminology arbiter: benchmark requester.
> Curated using the business-analyst lens · Last curated: 2026-10-20.
> Status: proposed vocabulary, not requester-approved definitions.

## How to use this

Use the source's words consistently. Definitions below are explicit proposals grounded in [idea.md](../idea.md) or labeled illustrative examples. They are not evidence about real translators. Confirm uncertain meanings with the benchmark requester before treating them as settled product rules. Changes must preserve the former meaning and identify affected documents.

## Terms

| Term | Proposed definition in the owner's vocabulary | Referent | Code identifier | Aliases — do not use |
| :-- | :-- | :-- | :-- | :-- |
| Solo freelance translator | A translator working independently who prepares their own client handover. | Segment named in idea.md | None | None established |
| Client | The person or organisation requesting the translator's work and handover requirements. | “client handover requirements” in idea.md | None | None established |
| Client requirement | Something the client asks to receive or have satisfied in the handover. Its permitted forms remain open. | Illustrative: a request for an accompanying file | None | “handover requirement” in idea.md refers to the same concept; use client requirement |
| Recorded client requirement | A client requirement entered in the local checklist. Recording does not establish that all requests were captured. | Candidate success signal in idea.md | None | None established |
| Requested file | A file the client asks the translator to include. | “omitted requested files” in idea.md | None | None established |
| Prepared file | A file the translator intends to send, available for comparison with a recorded client requirement. | Proposed brief scenario; no actual file supplied | None | None established |
| Local checklist | A list the translator keeps to track client requirements and their checked state. The meaning of local remains open. | Proposed capability in idea.md; brief question L | None | “checklist” is shorthand for this entry |
| Checked state | The translator's indication that a recorded client requirement has been checked against the prepared files. This is a proposed interaction, not proof of fulfilment. | Proposed MVP boundary in the brief | None | None established |
| Scattered notes | Client requirements retained in separate notes rather than one consolidated checklist. Their actual formats are unknown. | Problem hypothesis in idea.md | None | None established |

## Homonyms resolved

No confirmed homonym collision was supplied. “Recorded client requirement” deliberately distinguishes what was entered from everything the client requested; these must not be treated as interchangeable when measuring success.
